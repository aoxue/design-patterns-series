
```java
case "alipay" -> new AlipayGateway();
case "wechat" -> new WeChatGateway();
```

两处 switch 取自 `LegacyPaymentEntry`，查询使用同样的旧渠道分支。终端原文见重构演示后的实跑记录。

## 4. 框架影子（6:36–7:48）

| 镜号 · 时间码 | 台词 | 画面 | 代码切分 |
|---|---|---|---|
| 4.1 · 6:36–6:44 | Java 和 Spring 里，也有这种留给子类的创建方法。 | 系列固定小片头和变奏，左下标记「框架影子」 | 无 |
| 4.2 · 6:44–7:16 | 先看 Java 的抽象执行器。你提交一个任务，执行器会先把任务包起来，再交给执行方法，最后把可以追踪结果的对象还给你。包任务这一步由一个可以覆写的方法负责。它有默认实现，子类也可以换成自己的任务包装。就像刚才的支付流程，提交的主流程已经写好了，里面有一个创建点可以替换。 | 控制流卡上屏 `AbstractExecutorService`、`submit(Runnable)`、`newTaskFor()`、`execute()`，最后返回 `Future`。创建节点用当期蓝色加粗，角标「JDK 17」 | 方法名标签 |
| 4.3 · 7:16–7:48 | 再看 Spring 里的抽象工厂 Bean。以工厂的单例配置为例，父类在初始化时调用创建实例的方法，把生成的对象保存起来。创建什么对象，由子类实现那个方法。这里也把创建留给了子类。回到自己的项目，什么时候值得多写这些子类？ | 左侧 `AbstractFactoryBean` 初始化时点亮 `afterPropertiesSet()`，中间高亮 `createInstance()`，右侧亮出保存生成的对象。注明单例配置路径。框架两卡各留一个创建点，与 EP02 的 `createGateway()` 对齐 | 方法名标签 |

框架控制流核对见 [JDK 17 API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/concurrent/AbstractExecutorService.html)、[OpenJDK 17 源码](https://github.com/openjdk/jdk17u/blob/master/src/java.base/share/classes/java/util/concurrent/AbstractExecutorService.java) 和 [Spring 源码](https://github.com/spring-projects/spring-framework/blob/main/spring-beans/src/main/java/org/springframework/beans/factory/config/AbstractFactoryBean.java)。
