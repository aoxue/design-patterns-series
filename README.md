# 「码上购」设计模式系列 · 总纲

> 23 种 GoF 设计模式 × 26 期视频 | Java 17 | B 站主平台 | vibe 知识视频

## 1. 系列定位

**一句话**：用一套贯穿始终的虚构电商系统「码上购」，把 23 种设计模式讲成 26 期有连续剧情的 refactor 现场实录。

**目标观众**：1–5 年经验的 Java 后端；准备面试的应届生；听过设计模式但没在业务里用过的人。

**差异化三支柱**（每期必须做到，缺一不可）：

1. 案例全部来自真实业务代码（CRUD 里的设计模式），禁用 Shape/Dog/猫狗例子；
2. 每期必讲「什么时候别用它」；
3. 每期必有一段 JDK / Spring 源码关联（「框架影子」固定环节）。

vibe 视觉（lo-fi BGM、统一动效模板）是加分项，不替代以上三条。

## 2. 前提约定

| 项 | 决定 | 备注 |
|---|---|---|
| 语言 | Java 17（record、增强 switch 可用） | 全系列不换语言 |
| 平台 | B 站主平台，单期 8–12 分钟 | 抖音/小红书切 60 秒痛点版 |
| 更新节奏 | 默认周更（W = 周），可切双更（周期减半） | 见 operations.md |
| 期号规则 | **EP 编号 = 模式编号**，观众好记 | EP01–EP23 恰好对应 23 种模式 |
| 排期顺序 | 按「热度 × 难度」四梯队混排，不按 GoF 原书顺序 | 避免创建型 5 连坐劝退 |

> 以上为已锁定决策，不再重新讨论；确需变更，须明示理由并同步全部受影响文档。

## 3. 贯穿项目设定

- 项目名：**码上购**（虚构电商），包根 `com.mashanggou`
- 常用子包：`order`（订单）、`payment`（支付）、`promo`（促销）、`report`（报表）、`notify`（通知）
- 角色：一个人维护不动的小系统，随着每期 refactor 逐步「长大」——后期模式可引用前期成果，形成知识网
- 禁止出现与电商无关的例子（Animal、Shape、Coffee 等一律不用）

## 7. 换新电脑怎么开始

一次性准备：

```bash
# 1. GitHub 访问：新机器生成 SSH key 添加到账号（或 HTTPS + token），然后
git clone git@github.com:aoxue/design-patterns-series.git

# 2. 仅当本机全局 git 身份不是你想用于本项目的身份时（如公司配的机器），才需要仓库级覆盖：
cd design-patterns-series
git config user.name "你的名字"
git config user.email "你的邮箱"

# 3. 视频工程依赖（只在做视频时需要，详见 video/README.md）
cd video && npm install && pip install edge-tts
python tools/tts.py    # 音频不入库，新机器需重建样片配音
```

然后对 AI 说一句「**继续推进**」即可——agent 按 `AGENTS.md`「会话怎么接上」自动定位当前工作与下一步，不需要你复述任何背景或进度。

**不随仓库走的**（均为有意设计或机器本地）：`video/out/` 成片与 `video/public/audio/` 音频（可重建）；各机器本地的个人全局配置（如 ZCode 的 `~/.zcode/AGENTS.md` 个人准则，换机建议手动同步一份）。
