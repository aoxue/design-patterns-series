## 1. 系列定位

用一套贯穿始终的虚构电商系统「码上购」，把 23 种设计模式讲成有连续剧情的重构实录。全系列包括 23 期正片、1 期先导和 1 期完结特辑。

**目标观众**：1–5 年经验的 Java 后端；准备面试的应届生；听过设计模式但没在业务里用过的人。

**EP01–EP23 正片的三支柱**：

1. 案例全部来自真实业务代码（CRUD 里的设计模式），禁用 Shape/Dog/猫狗例子；
2. 每期必讲「什么时候别用它」；
3. 每期必有一段 JDK / Spring 源码关联（「框架影子」固定环节）。

vibe 视觉（lo-fi BGM、统一动效模板）是加分项，不替代以上三条。

## 2. 前提约定

| 项 | 决定 | 备注 |
|---|---|---|
| 语言 | Java 17（record、增强 switch 可用） | 全系列不换语言 |
| 平台 | B 站主平台，单期 8–12 分钟 | 抖音/小红书切 60 秒痛点版 |
| 更新节奏 | 默认周更（W = 周），可切双更（周期减半） | 见 operations.md |
| 期号规则 | **EP 编号 = 模式编号**，观众好记 | EP01–EP23 恰好对应 23 种模式 |
| 排期顺序 | 按「热度 × 难度」四梯队混排，不按 GoF 原书顺序 | 避免创建型 5 连坐劝退 |

> 以上为已锁定决策，不再重新讨论；确需变更，须明示理由并同步全部受影响文档。

## 3. 贯穿项目设定

- 项目名：**码上购**（虚构电商），包根 `com.mashanggou`
- 常用子包：`order`（订单）、`payment`（支付）、`promo`（促销）、`report`（报表）、`notify`（通知）
- 角色：一个人维护不动的小系统，随着每期 refactor 逐步「长大」，后期模式可引用前期成果，形成知识网
- 禁止出现与电商无关的例子（Animal、Shape、Coffee 等一律不用）

## 4. 排期总表

> **本表 = 全项目排期与粗状态的唯一事实源**；单集细粒度进度以脚本附录 D 为准。周更假设；双更则 W 减半。
>
> 「制作中」覆盖脚本、配音、画面、渲染与验收全过程。「当前阶段／下一步」是附录 D 的简要摘要，推进或阻塞变化时由制片人同步更新，不另建进度文件。
>
> 状态取值与流转规则：
>
> - `未开始 → 制作中`：详案就位，开工分镜脚本；
> - `制作中 → 已存稿`：完成 [SOP §6](production-sop.md#6-每期产出物清单) 的适用产出物，通过 §7–8 验收并在附录 D 登记交付版 MP4。60 秒切片按发布后节奏安排；
> - `已存稿 → 已发布`：B 站上线；发布后 48 小时数据回填 operations.md 复盘表。

W0 从 M1 达标后的开播周起算。EP01–EP06 先从日常改需求切入，EP07–EP12 处理系统边界，EP13–EP19 处理规模和业务变体，EP20–EP23 回到已有业务线拆解复杂规则。表内钩子用于选题，标题和详案在对应梯队开工前确认。

## 5. 里程碑与决策点

| 节点 | 条件 | 动作 |
|---|---|---|
| M1 · 开播 | 存稿 ≥ 4 期（EP00–EP03 全部完成） | 发布 EP00，进入周更 |
| M2 · 复盘①（W6） | 第一梯队 6 期数据 | 完播率 > 30% → 按表推进第二梯队；< 20% → 调整钩子/时长后 EP07 重试 |
| M3 · 复盘③（W19） | 冷门模式数据预判 | EP20–23 可压缩至 5 分钟或两期合并，不必硬撑格式 |
| M4 · 完结（W24） | EP24 发布 | 输出全景图长图（可独立传播物料） |
